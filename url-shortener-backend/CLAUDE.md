# Project Instructions for Claude Code

This document contains permanent instructions and guidelines for any Claude Code session working on the URL Shortener project.

## Core Principles
- **Context First**: Always inspect the project documentation (`README.md`, `ARCHITECTURE.md`, `DECISIONS.md`, `LEARNING.md`, `TODO.md`) before making changes.
- **Source of Truth**: Treat the existing code as the primary source of truth.
- **Stability**: Do not rewrite working functionality without a strong, documented reason.
- **Communication**: Explain important design decisions and trade-offs before implementing them.
- **Documentation**: Update relevant documentation (`ARCHITECTURE.md`, `TODO.md`, etc.) whenever architecture or major functionality changes.
- **Persistence**: Keep `TODO.md` updated after significant work to ensure continuity across sessions.
- **No Assumptions**: Do not assume context from previous conversations; rely on the documentation in the repository.

## Development Workflow
1. **Research**: Explore the codebase and read the current documentation.
2. **Plan**: Propose a design or implementation plan.
3. **Learn**: For new features, follow the `LEARNING.md` process (Requirements $\rightarrow$ Design $\rightarrow$ Concepts $\rightarrow$ Trade-offs $\rightarrow$ Implementation $\rightarrow$ Testing $\rightarrow$ Documentation).
4. **Implement**: Write the code following the project's existing naming and structural patterns.
5. **Verify**: Add or update tests to ensure correctness.
6. **Document**: Update all relevant project files.
